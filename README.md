# Adaptive Data Quality Platform

A configuration-driven CSV data quality pipeline with schema checks, profiling, validation, optional anomaly detection, auto-healing, quality scoring, audit records, and a Streamlit dashboard. FastAPI is the source of truth for pipeline results; the dashboard displays API responses and does not reimplement pipeline logic.

## Project structure

- `src/api/` — FastAPI application, routes, and upload pipeline service
- `src/core/` — pipeline orchestration and result serialization
- `src/schema/`, `src/profiling/`, `src/validation/` — schema and data quality checks
- `src/auto_healing/`, `src/anomaly_detection/`, `src/quality/`, `src/audit/` — repair plugins and analysis outputs
- `config/` — pipeline, schema, validation, healing, and scoring configuration
- `frontend/` — Streamlit dashboard and API client
- `tests/` — unit and API tests

## Requirements and installation

Use Python 3.11 for the project environment. From the repository root in PowerShell:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

The FastAPI server command uses Uvicorn, which is included in `requirements.txt`.

## Start the backend

Open a terminal at the repository root and run:

```powershell
python -m uvicorn api.app:app --app-dir src --reload --host 127.0.0.1 --port 8000
```

The API will be available at `http://127.0.0.1:8000`. Check its status at `http://127.0.0.1:8000/health`.

## Start the frontend

In a second terminal, activate the same environment and run:

```powershell
.\.venv\Scripts\Activate.ps1
$env:API_BASE_URL = "http://127.0.0.1:8000"
streamlit run frontend/app.py
```

`API_BASE_URL` is the only frontend configuration variable. It defaults to `http://localhost:8000`; set it when the API runs at another address. The browser uses this address for the cleaned CSV download link, so it must be reachable from the browser as well as the Streamlit server.

## Example workflow

1. Start the backend and frontend.
2. Open the Streamlit URL shown in the frontend terminal.
3. Upload a CSV and select **Run pipeline**.
4. Review the before/after quality scores, metrics, schema and validation results, healing actions, anomaly status, and audit details.
5. Select **Download cleaned CSV** to retrieve the output for that run.

The default schema is configured in `config/pipeline_config.yaml`; uploaded datasets missing required columns receive a schema validation error. `data/sample_data/employees.csv` is available as a sample dataset.

## API endpoints

| Method | Endpoint | Description |
| --- | --- | --- |
| `GET` | `/health` | Returns `{"status":"ok"}` when the API is available. |
| `POST` | `/pipeline/run` | Runs the pipeline on multipart form data using the field name `file`; supports CSV. |
| `GET` | `/pipeline/{run_id}/download` | Downloads the cleaned CSV generated by that run. |

A successful pipeline response contains the serialized schema, profiles, validation results, healing results, anomaly result, quality scores, before/after metrics, audit trail, execution time, run ID, and output metadata. Missing required schema columns produce HTTP 422 with a structured result in `detail`; other upload and execution errors use HTTP 400, 415, or 500 as appropriate.
